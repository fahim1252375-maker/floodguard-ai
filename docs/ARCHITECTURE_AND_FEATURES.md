# FloodGuard AI — Architecture & Advanced Feature Map

## Product concept

FloodGuard AI links three layers that are often presented separately: **flood context**, **community health preparedness**, and **response operations**. It is a decision-support research prototype for flood-prone areas of north-eastern Bangladesh.

## Architecture at a glance

```text
React 19 + TypeScript + Tailwind + Vite
        │
        ├── 20 feature views, charts, Leaflet maps, bilingual UI
        ├── PWA service worker / offline app-shell caching
        └── Typed client utilities and persistent user preferences
        │
Express API (server.ts)
        ├── Open-Meteo Weather / Flood API proxy
        ├── Optional Gemini natural-language endpoints
        ├── Report validation, rate limiting and moderation
        ├── Admin PIN verification and alert publishing
        └── Operations API and Server-Sent Events
        │
Persistence and engines
        ├── SQLite: operations history, events, rules, check-ins, subscribers, audit
        ├── JSON files: community reports and public alerts
        └── Deterministic risk, trend, planning and validation utilities
```

## Advanced capability groups

### 1. Flood intelligence and scenario exploration

- Live hourly precipitation context from Open-Meteo where the API is reachable.
- Daily GloFAS modelled river-discharge estimates through the Open-Meteo Flood API; this is a grid-cell estimate, not a local river-gauge observation.
- Statistical trend projections and ensemble-style recorded-series comparisons, clearly labelled as derived scenarios rather than calibrated flood probabilities.
- Rainfall and upstream-influx simulator for hypothetical scenario exploration.
- Historical rainfall archive when available, with illustrative stage traces explicitly separated from measured historic stage data.
- BasinTwin graph for explaining assumed basin connections; it is not a hydrodynamic routing engine.

### 2. Flood-to-health preparedness

- Hand-weighted planning indicators for diarrhoeal/enteric illness, skin infection and snakebite preparedness.
- Shelter readiness and preposition-planning workflows for example stocks such as ORS, clean water and first-aid supplies.
- RouteSafe view for exploring illustrative passability and clinic-access scenarios.
- Fixed bilingual safety guidance for health-preparedness content; safety-critical instructions are not generated by the LLM.

### 3. Community ground-truth and operations

- Consent-based community reports with server validation, rate limiting and pending-by-default moderation.
- Public report responses omit reporter contact numbers.
- SQLite-backed check-ins, subscriber preferences, alert rules, station threshold overrides and an audit trail.
- Server-Sent Events for live operations updates.
- Responder desk, bilingual situation reports and queued SMS outbox. A gateway adapter is required for actual outbound SMS.

### 4. AI, transparency and resilience

- Optional Gemini integration for selected conversational and prediction-language features.
- Deterministic calculations remain separate from generated text.
- Data Health and provenance surfaces help users distinguish LIVE, MODELLED, DERIVED, CROWD-SOURCED and SIMULATED inputs.
- English and Bangla interface, PWA install support and cached app shell for previously loaded screens.

## Data-provenance rule for presentations

Every demo should state which values are live API responses, model estimates, calculated indicators, community-submitted records or simulated examples. Do not describe demo station stages as live BWDB telemetry, GloFAS as a gauge reading, heuristic health scores as clinical predictions, or route examples as verified safe routes.
